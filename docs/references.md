## 📌 모든 레퍼런스 분석 시 공통 작업 원칙 (필수)

> 내가 주는 레퍼런스 사이트는 **대부분 AI 크롤링이 차단되거나 소스코드 접근이 불가**하다.
> 따라서 분석은 항상 다음 방식으로 진행한다.

1. **반드시 실제 브라우저를 띄워서 직접 확인한다.** (WebFetch·크롤링 결과만 믿지 않는다)
2. **매우 조금씩 스크롤하면서 캡처한다.** — 섹션 전환·모션 중간 상태가 빠지지 않도록 촘촘하게.
3. **캡처한 이미지들을 기반으로** 색상·타이포·레이아웃·컴포넌트·모션을 분석한다.
4. **⚠️ 모든 이미지를 빠짐없이 분석한다. 앞부분만 대충 보고 끝내는 것은 금지.**

### 저작권 관련 기준
- 3D 애니메이션 프레임 데이터, 폰트 파일, 사이트 소스코드 **자체를 복제/추출하지 않는다.**
- 추출한 **스펙(색상값·폰트명·치수·구조·모션 패턴)을 참고해 새로 제작**하는 방식으로 진행한다.

## 01. Hut 8

- **URL**: https://hut8.com

- **분류**: 전체 무드 / 컬러 / 타이포 / 레이아웃 / 모션(3D 스크롤)
- **한 줄 요약**: "다크 배경 + 오프화이트 텍스트 + 라임그린 액센트" 3색 구조에, 자간을 극단적으로 좁힌 100px 헤드라인과 canvas 기반 아이소메트릭 3D 스크롤 씬을 얹은 인프라/에너지 기업 사이트.

### 분석 내용

픽셀 단위로 똑같이 재현하기 위해, 실제 페이지에서 추출한 값(폰트, 색상, 레이아웃, 컴포넌트) 기반으로 정리한 디자인 스펙. 디자이너/개발자에게 전달하면 "이 사이트와 100% 동일하게 만들어달라"는 요청을 정확히 이해할 수 있는 수준.

#### 색상 팔레트
배경은 순수 블랙이 아니라 거의 블랙에 가까운 다크그레이(`rgb(8,8,8)`)를 기본으로 쓰고, 텍스트는 완전한 화이트가 아니라 살짝 부드러운 오프화이트(`rgb(248,248,248)`, `rgb(232,232,232)`)를 씁니다. 그리고 포인트 컬러로 형광 라임그린(`rgb(179,255,0)`, 헥스로는 대략 `#B3FF00`)을 CTA 버튼이나 강조 요소에만 제한적으로 사용합니다. 보조 그레이 톤으로 `rgb(168,168,168)` 같은 중간 회색이 캡션이나 부가 텍스트에 쓰입니다. 즉 팔레트는 **"다크 배경 + 오프화이트 텍스트 + 라임그린 액센트" 3단 구조**로 요약됩니다.

| 역할 | 값 |
|---|---|
| 배경 (base) | `rgb(8,8,8)` |
| 텍스트 primary | `rgb(248,248,248)` |
| 텍스트 secondary | `rgb(232,232,232)` |
| 텍스트 muted / 캡션 | `rgb(168,168,168)` |
| 액센트 (CTA·강조) | `rgb(179,255,0)` ≈ `#B3FF00` |

#### 타이포그래피
전체 폰트는 **"ITC Franklin Gothic Std"** 라는 산세리프 계열 유료 폰트입니다(대체 시 Franklin Gothic이나 Helvetica Neue Condensed 계열로 근사 가능). 헤드라인(H1)은 100px 크기, line-height도 100px로 딱 맞춰(즉 행간 여유 없이 타이트하게), font-weight 500, 자간(letter-spacing)은 -3px로 글자를 촘촘하게 붙여서 크고 강렬한 느낌을 줍니다. 서브헤딩(H2)은 60px, weight 400으로 더 가볍게 처리합니다. 본문 텍스트는 기본 16px, weight 400입니다. 이 **"타이트한 자간의 초대형 헤드라인"** 이 이 사이트 타이포그래피의 핵심 특징입니다.

| 요소 | size | line-height | weight | letter-spacing |
|---|---|---|---|---|
| H1 | 100px | 100px (1.0) | 500 | -3px |
| H2 | 60px | — | 400 | — |
| body | 16px | — | 400 | — |

#### 레이아웃 / 그리드
콘텐츠 섹션의 최대 너비는 **1600px**로 제한되어 있고, 내부 컨테이너 중 하나는 **240px 고정폭**(사이드 라벨이나 작은 카드용으로 추정)입니다. 전체적으로 여백을 넉넉히 주는 풀블리드(full-bleed) 레이아웃과 중앙 정렬된 넓은 콘텐츠 폭을 병행합니다. 버튼은 `border-radius: 0`(직각 모서리), 테두리 없음, 배경은 라임그린 / 텍스트는 블랙인 단순한 사각 버튼 스타일입니다.

#### 내비게이션 구조
상단 고정 헤더에 로고(홈 링크) + 토글 메뉴 버튼 + 메인 메뉴(Home, Our Platform, About Us, News & Insights, Investors)가 있고, "Our Platform" 하위에 **Power / Digital Infrastructure / Compute** 3개 서브 링크가 존재합니다. 푸터 쪽에는 Careers, HPC Client Portal, Terms, Privacy Policy 등 부가 링크가 있습니다.

#### 모션 / 애니메이션 구조 (가장 복잡한 부분)
페이지 안에 `canvas` 요소가 1개, `svg`가 54개 존재합니다. 이는 아이소메트릭 3D 장면(Power, Digital Infrastructure, Compute 섹션)이 WebGL 기반 canvas 렌더링(Three.js류) 또는 사전 렌더링된 시퀀스 프레임을 canvas에 그리는 방식으로 구현되어 있다는 뜻입니다. 스크롤에 따라 섹션이 화면에 **"고정(pin)"** 된 채 애니메이션만 진행되는 스크롤-트리거 방식(흔히 GSAP ScrollTrigger나 유사 라이브러리로 구현)이 반복적으로 쓰입니다. "Our Impact" 섹션의 **숫자 카운트업(0→710MW)**, "Powering the Future"의 **무한 루프 텍스트 캐러셀**, **파티클/도트 그리드 웨이브 배경**도 모두 이 스크롤 기반 모션 시스템의 일부입니다.

#### 똑같이 만들려면 필요한 것 (전달용 5요소)
1. **폰트** — ITC Franklin Gothic Std (라이선스 구매 필요, 대체 폰트 사용 시 근접한 산세리프 + 타이트 자간으로 조정)
2. **컬러** — 배경 `rgb(8,8,8)` / 텍스트 `rgb(248,248,248)` / 포인트 `rgb(179,255,0)` 3색 팔레트
3. **타이포 스케일** — H1 100px / 자간 -3px / weight 500, H2 60px / weight 400
4. **레이아웃·컴포넌트** — 최대 1600px 폭 섹션 레이아웃, 각진(radius 0) 버튼
5. **모션 엔진** — canvas 기반 3D 아이소메트릭 씬 + 스크롤 핀 애니메이션 + 카운트업 + 무한루프 텍스트 캐러셀

이 5가지 요소(색, 폰트, 레이아웃, 컴포넌트, 모션 엔진)를 그대로 구현하면 시각적으로 거의 동일한 결과물이 나옵니다.

### 우리 사이트에 적용할 점
- **3색 제한 팔레트 원칙** — 다크 base + 오프화이트 텍스트 + 액센트 1개. (액센트 색은 kodekorea 브랜드에 맞게 교체 검토)
- **순수 블랙/화이트를 피하는 감각** — `#000`/`#fff` 대신 `rgb(8,8,8)`/`rgb(248,248,248)`. 눈이 편하고 고급스러워 보이는 핵심 디테일.
- **초대형 헤드라인 + 음수 자간 + line-height 1.0** — 임팩트의 대부분이 여기서 나옴.
- **radius 0 각진 버튼** — 엔지니어링/인프라 톤과 일치.
- **스크롤 핀 + canvas 3D 씬** 구조. 구현 시 `cinematic-3d-motion-site` 스킬이 이 사이트를 레퍼런스로 다루므로 연계 가능.
- 숫자 카운트업, 무한 루프 텍스트 캐러셀은 재사용 가치 높은 개별 컴포넌트.

### 적용하지 않을 점 / 주의
- **ITC Franklin Gothic Std는 유료 폰트** — 라이선스 없으면 사용 불가. 대체 후보를 별도 검증 필요 (자간 -3px에서 자연스럽게 붙는 폰트여야 함).
- 100px H1은 **데스크톱 기준값**. 반응형 스케일(모바일 축소 규칙)은 이 스펙에 없으므로 별도 설계 필요.
- 3D 프레임 데이터·폰트 파일·소스코드 복제 금지. 스펙 참고 후 신규 제작.
- canvas 3D + 스크롤 핀은 **성능 비용이 큼** — 저사양/모바일 폴백 전략 필수.

## ✅ 01-A. 브라우저 직접 검증 결과 (2026-07-27)

위 분석본을 실제 사이트에서 확인했다. **색상·폰트·1600px 폭은 정확했고, 타이포 스케일과 전체 무드에는 중요한 오차가 있었다.**

### 원본 CSS 변수 (사이트에서 그대로 추출)

**컬러 — 원본 분석이 놓친 것 포함 전체**
```
--color-off-black:      #080808   ✅ 확인 (body 배경)
--color-off-white:      #f8f8f8   ✅ 확인
--color-bright-green:   #b3ff00   ✅ 확인 (액센트)
--color-bright-green-lt:#baff1a   🆕 (호버/보조)
--color-grey-100:       #e8e8e8   ✅ (=rgb 232, 헤딩 텍스트)
--color-grey-175:       #a8a8a8   ✅ (=rgb 168, 캡션)
--color-grey-150/200/300/400/500/600/700  🆕 그레이 램프 8단계
--color-bright-blue:    #30f      🆕 (거의 안 쓰이지만 정의돼 있음)
--color-sage-green:     #bcbfb0   🆕
--color-dimmed-white:   rgba(248,248,248,.1)  🆕 (보더/디바이더용)
```

**타이포 스케일 — ⚠️ 원본 분석의 가장 큰 오차**

원본은 "H1 100px / 자간 -3px / weight 500"이라고 했으나, 실제 토큰상 **100px는 heading-2**다. 진짜 heading-1은 **255px**.

| 토큰 | 데스크톱(lg/md) | 모바일 | line-height | letter-spacing |
|---|---|---|---|---|
| heading-1 | **255px** | 130px | 1 | **-0.04em** |
| heading-2 | **100px** | 60px | 1 | -0.03em ( = 100px에서 -3px ✅) |
| heading-3 | 60px | 40px | 1 | -0.03em |
| heading-4 | 44px | 30px | 1 | -0.02em |
| body-1 | 60px | 26px | 1 | -0.02em |
| body-2 | 36px | 36px | 1.2 | -0.02em |
| body-5 | 16px | 16px | 1.5 | -0.02em |

- **자간을 px가 아니라 em으로 정의**한다(-0.04 / -0.03 / -0.02em 3단계). 크기가 바뀌어도 비율이 유지되는 방식 — 우리가 따라야 할 쪽은 이것.
- line-height는 헤딩 전부 **1**, 본문은 1.2~1.5.
- 폰트 weight: h2=400, h3=500 (원본의 "H1 500 / H2 400"과 반대 방향).

**그리드·간격**
```
--grid-max-width: 1600px   ✅ 원본 확인
--columns:        8        🆕 (8컬럼 그리드)
--grid-padding:   24px     🆕
--gutter-width:   24px     🆕
--space-*: 16 / 24 / 32 / 48 / 64 / 72 / 96 / 128 / 144 / 168 / 196px  🆕
```
- 원본의 **"240px 고정폭 컨테이너"는 토큰에 없다.** 근거 불명이므로 무시할 것.

### ⚠️ 가장 큰 정정: 이 사이트는 다크 단색이 아니다

원본은 "다크 배경 + 오프화이트 텍스트 + 라임" 3색 구조로 요약했지만, **실제로는 다크 → 라이트 → 다크로 크게 반전한다.**

- **히어로**: 블랙(#080808) 배경 + 대각선 광선 텍스처. 헤드라인은 60px(heading-3).
- **Power / Digital Infrastructure / Compute 3D 씬**: **거의 흰 배경**(밝은 회색)에 파스텔 컬러 도트 그리드, 흰색·연회색 아이소메트릭 3D 모델. **라임은 배경색이 아니라 "에너지가 흐르는 선"으로만** 쓰인다. 화면의 90%가 흰색인 구간이 상당히 길다.
- **Our Impact**: 흰 배경 + 도트 지형.
- **Powering the Future / 푸터**: 다시 블랙.

→ 우리가 참고할 원칙은 "다크 팔레트"가 아니라 **"무채색 베이스(밝든 어둡든) + 라임 액센트 1개, 섹션 단위로 명암을 크게 반전"** 이다.

### 섹션별 실제 내용 (원본이 뭉뚱그린 부분)

- **3D 아이소메트릭 씬**: 풍력터빈·태양광 패널·냉각탑·변전소·데이터센터가 놓인 흰 지면 위를, **카메라가 라임색 전력선을 따라 계속 이동**한다. 좌측에 `Power` + `Layer 1.0` 라벨이 고정으로 붙어 있고, 씬 위에 원형 아이콘 핀들이 떠 있다. 즉 3개 층(Layer 1.0 → 2.0 → 3.0)을 **하나의 연속된 지형을 이동하며** 보여주는 구조.

창 리사이즈가 브라우저에 먹지 않아 화면 캡처는 못 했지만, **스타일시트의 @media 규칙을 직접 추출**해 실제 값을 확보했다. (`html { font-size: 62.5% }` → 1rem = 10px)

- 조명: 어두운 올리브·차콜 톤. 단일 강한 광원.
- 좌상단: `Robin - Creative developper` / `contact@robin-thomas.me` (모노스페이스).
- 히어로 카피: **콘덴스드 세리프**(Sansita 계열, Kanit도 병용)로 `Hi ! I am Robin, french creative developer and looking for opportunities` → 이어서 `Freelance / Or permanent job / Remote`. **글자 단위 타이프라이터 + 회색→흰색 페이드**로 등장, 텍스트 블록이 위로 흘러가며 순환.
- 우상단: **FWA "Of the Day" 노란 리본 배지**(대각선).
- 하단 좌: `Scroll to continue` + **가로 진행 바**(빨강 채움).
- 하단 중앙: 마우스 휠 아이콘 + 아래 화살표 셰브론(펄스 애니메이션).
- 하단 우: Instagram / LinkedIn 아이콘 + **사운드 비주얼라이저 버튼**(4개 막대가 오디오에 맞춰 실시간으로 늘었다 줄어듦).

**구조 (DOM에서 확인)**
- 네이티브 스크롤 없음(`document.scrollHeight === innerHeight`). 휠 입력을 3D 씬 타임라인으로 변환하는 **완전 가상 스크롤**.
- 클래스명에 `acte-four`, `no-acte-four` → 사이트가 **여러 "Acte(막)"** 로 구성됨.
- `points-container` 안에 **`point empty` 요소 14개** → 포인트 수집 게이미피케이션.
- 하단 빨강 바는 진행률이 아니라 **스크롤 속도(가속) 게이지** — 스크롤을 멈추면 줄어든다. **가득 채워야 다음 막으로 넘어간다.**
- 스택: Three.js + GSAP. 폰트: Kanit(300/400/700) + Sansita.

### 핵심 발견
- **스크롤 = 가속 페달**. 스크롤 양이 아니라 **속도**가 파라미터이고, 임계값을 못 채우면 Acte 1이 무한 반복된다. 자동화가 뚫지 못한 이유이자, 이 사이트가 "읽는 것"이 아니라 "조작하는 것"임을 보여주는 장치.
- **막마다 색채 전략이 완전히 다르다**: Acte 1 거의 무채색 초저조도 → Acte 2 다크 + 빨간 포인트 → 우주 무채색 → 워프 시안·마젠타 폭발 → Acte 4 밝은 파스텔. **어둠에서 빛으로** 가는 한 방향 여정.
- **화이트아웃을 씬 전환 장치로 반복 사용** — 3D 씬을 갈아끼우는 로딩·전환 비용을 "빛에 삼켜지는" 연출로 감춘다.
- 스킬 정보(Figma / Three.js / R3F / Zustand)를 리스트가 아니라 **행성 궤도 라벨**과 **레트로 3D 타이포**로 전달한다.
- 최종적으로 포트폴리오 프로젝트 목록조차 **게임 스테이지를 걸어다니며 수집**하는 구조로 보인다(포인트 14개).

### 우리 사이트에 적용할 점
- **START 게이트** — 무거운 3D를 쓸 때 프리로더를 수동 진입 버튼으로 바꾸면, 대기 시간이 "기다림"이 아니라 "준비"로 읽힌다. (#03 HLE의 무한 프리로더 문제에 대한 해답)
- **스크롤을 물리 입력으로 쓰는 발상** — 스크롤 양이 아니라 **스크롤 속도**를 파라미터로 삼는 인터랙션.
- **오브젝트가 경로를 따라가는 3D 씬** — 카메라만 움직이는 Hut 8/HLE와 달리, 주인공 오브젝트(구슬)가 이동하고 카메라가 따라간다. 사용자의 "내가 움직이고 있다"는 감각이 훨씬 강함.
- 사운드 비주얼라이저 버튼, FWA 배지 자리 같은 **우하단 유틸리티 클러스터** 배치.
- 로더 버튼 라벨을 글자 단위로 교체하는 마이크로 인터랙션.
- **화이트아웃(백색 구체 팽창)을 씬 전환 장치로 재사용** — 무거운 3D 씬 교체를 연출로 감추는 실용적인 기법. kodekorea에서 섹션 간 3D 씬을 바꿔야 할 때 그대로 쓸 수 있다.
- **막마다 색을 완전히 갈아엎는 여정 설계** — 어둠(무채색) → 폭발(시안·마젠타) → 밝음(파스텔). 한 팔레트를 끝까지 유지하는 #01·#03과 정반대 전략인데, "이동했다"는 감각은 이쪽이 훨씬 강하다.
- **정보를 리스트가 아니라 오브젝트에 붙이는 발상** — 스킬을 행성 궤도 라벨로, 직무를 3D 압출 타이포로.
- 하단 좌측 라벨이 상황에 따라 바뀌는 처리(`Scroll to continue` → `Follow stairs`) — **현재 해야 할 조작을 한 줄로 계속 알려주는** 게임식 안내.

### 적용하지 않을 점 / 주의
- **네이티브 스크롤 완전 제거는 위험하다.** 키보드 스크롤·스크롤 복원·접근성이 모두 깨지고, 자동화/크롤러/스크린리더에서 콘텐츠 접근이 불가능해진다. 실제로 이 사이트는 그 때문에 자동 분석 자체가 막혔다.
- **진입 장벽이 높다** — 로딩 20초 + START 클릭 + 빠른 연속 스크롤 요구. 포트폴리오라 가능한 설계이며, **기업 사이트에는 부적합**.
- 게이미피케이션(포인트 수집)은 목적이 분명할 때만. B2B 사이트에서는 정보 전달을 방해할 수 있음.
- 히어로 씬이 매우 어두워서(거의 검정) 저휘도 모니터·야외에서 아무것도 안 보일 수 있음.
- **"속도 임계값을 못 채우면 진행 불가"는 치명적인 UX 리스크.** 트랙패드·저감도 마우스·접근성 도구 사용자는 영영 Acte 1에 갇힌다. 실제로 자동화·느린 입력으로는 아무리 스크롤해도 넘어가지 못했다. 기업 사이트에 이런 게이트를 두면 안 된다.
- 45초 녹화 기준 **Acte 1에만 16초**가 소요된다. 정보 도달까지의 지연이 지나치게 길다.

### 후속 작업 (완료)
- [x] **Acte 2 이후 구간 캡처 완료** — 자동화로는 두 가지 벽이 있었고, 결국 화면 녹화로 뚫었다.

  **로드 벽 (해결)**: 재방문 시 React가 `#root`에 마운트되지 않고 흰 화면으로 끝남. 번들(`index-*.js`, 3.8MB)은 200으로 정상 수신되는데도 실패하고, 일반 새로고침·새 탭 모두 안 됨. → **하드 리로드(Ctrl+Shift+R)로 해결.** 캐시된 에셋이 깨진 채 남는 문제로 보인다.

  **입력 벽 (자동화 불가로 확정)**: 스크롤 속도 게이지를 임계값까지 채워야 다음 막으로 넘어가는데, 게이지가 40~50%에서 멈추고 입력을 멈추면 즉시 감쇠한다. 시도한 5가지 전부 실패:
  1. 휠 틱 소량 연타(amount 2~5) / 2. 휠 틱 대량 무중단 배치(amount 10 × 15회) / 3. JS 합성 `WheelEvent` 260회 연속 디스패치(변화 없음 — isTrusted 검사 추정) / 4. 키보드 `Down` 100회 반복(무반응) / 5. 마우스 드래그(하→상) → 스크롤이 아니라 텍스트 선택만 됨.
  
  근본 원인은 도구 호출 사이의 지연 — 사람 손처럼 끊김 없는 연속 입력을 만들 수 없다.

  **해결**: 사용자가 직접 스크롤하며 45초 화면 녹화 → #02와 동일한 프레임 추출 방식으로 전량 분석. 이 방법이 유일하게 확실했다.
